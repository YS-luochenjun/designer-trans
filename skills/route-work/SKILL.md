# Route 与 Work 交接

1. **锁定事实**：核任务、素材、语言、当前尝试、媒体 SHA、原请求和剩余额度。
   完成条件：区分当前事实、历史输出、未知结果与用户已暂停。
   读取执行器 `budget_policy`；测试不限额时，旧工单动作数只作历史参考，
   以实际进展和可用方法安排下一项，消耗持续记账。
2. **识别意图**：信息询问直接答复；明确修改追加要求并通知相关 Work；
   仅需求歧义时由 Route 提出一个问题及 2 到 4 个业务选项。
   完成条件：回复说明已转达、排队或实际执行中的哪一步，信息询问不改变制作。
3. **安排工作**：Route 给出目标、影响范围、证据和换法条件；Work 自主选用实际可用工具，
   沿用原会话和已接受结果。完成条件：在安全边界接收方向，原在途候选保留，
   不用变更措辞重复相同失败配方。
4. **报备结果**：Work 提交产物身份、已解决和未解决范围、验证及已知/未知费用；
   Route 选择下一合法阶段或有上限的返工。完成条件：清底缺口没有被译字掩盖，
   下游只引用质量与依赖核验通过的当前产物。
   用户先看 Route 的一到三句简短汇报；Work 日志和原始诊断可展开查询。
   已下发问题与已执行检查分开：缺执行记录时安排实际 Work，不循环索取不存在的回执。
5. **停止与提问**：缺能力、原结果未知或原额度耗尽时保留具体阻塞。
   用户只决定业务偏好与最终视听验收。完成条件：Route 没有把技术参数转给用户，
   没有循环重投、扩额或自动批准。

困难素材先区分“本次方法失败”和“整项无可执行路线”。核实际 available_tools，
对其他未解决实例及 image_edit/wan 等可用替代方法评估收益和风险，不要求全部付费试用。
本地工单限制不撤销 Route 后续换法权限；原生生图不可用不等于 KIE 不可用。
停止前用 remaining_assessments 覆盖每个剩余实例并给证据；仍有可做范围就派下一项。
完成条件：没有把单个难段的失败外推全片，普通瑕疵按实际观看影响接受并披露，
系统性残字不以“尽力”或高分放行。原审核缺陷随 Route 返工进入对应素材、语言的工作包。

用户明确允许新执行时，先核一次授权及追加动作窗口，再从现有接受底片重新评估。
程序归档旧工单与收尾控制，累计轮数和费用继续计数；Work 按当前工作包观察、
选法、制作、检查改区与未改区，再向 Route 报备。普通失败不是用户暂停。

用户明确要求丢弃旧清底与下游时，改用绑定版本的阶段重置；新节点从原片、0接受开始。
验证旧产物备份后移出当前步骤，保留原费用与未知请求核账身份。独立音频继续沿用。
重置回执、维护恢复和实际新制作分别核验，不能把“已重置”汇报为“已做完”。

详细运行合同见 [Route 与 Work](../../docs/architecture/route-work.md)；
清底与成片门禁见[逐阶段质量](../../docs/operations/stage-quality.md)。
重启或报备中断后，按运行合同核对原请求与既有事件；补交缺失事实报告后，
仍由 Route 在原额度内决定后续工作。完成条件：报告已接收与 Work 已执行分别有据。
