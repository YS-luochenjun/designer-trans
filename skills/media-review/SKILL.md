# 媒体审阅

这是本项目的版本化流程技能，由资源目录在 clean、review 节点提供。评分与边界定义统一读取知识资源 `video-translation.clean-quality`（项目正文 `knowledge/clean-quality/policy.json`），不在本文件重复维护阈值。

## 局部清底复核

1. **锁定版本**：读取原片、修复前底片、候选的身份及frame_clock。完成条件：候选的input_sha256等于当前底片SHA，能够对应三组画面；不同基底先本地重合成再看。
2. **先看边界**：按评分知识中的required_evidence核对首尾内外帧，再看内部时间序列。完成条件：必查帧已提供且实际frame_index正确；缺帧先inspect，不用中间帧或音频尾部重复帧充数。
3. **归因再评分**：原片对底片识别既有问题，底片对候选识别本轮变化。按评分知识viewing_standard区分普通外观瑕疵与实质损伤；少量发丝未接齐不自动等于subject_damage。完成条件：缺陷注明对象、帧号、继承或新增、正常观看影响及实际证据类型；达到门槛且无硬伤即accept，轻微差异写入limitations后继续。
4. **诊断生成链路**：候选出现结构损伤且原因不明时，调用inspect_pipeline，对照已保存的模型输入、原始返回和本地缩放结果。这些图按裁切相对时间标注，不能当原片帧号。原始返回已经有的位移、变形或新增物体属于模型结果问题；仅贴回后出现的问题才继续核查本地帧映射和坐标。完成条件：归因有对应画面；无法判定则明确未知，保留原回执，不重新提交相同请求。链路检查后需要inspect恢复三方画面，才能验收。
5. **拒绝并继续**：确认候选有硬伤后，用reject_candidate保存理由、证据及评分。拒绝只归档候选，不删除文件、不改变底片、不计入覆盖。优先推进其他未解决实例；重做本实例须有新的方法或范围证据，模型结构损伤不能靠同样补片重贴解决。完成条件：坏候选不会进入可复用列表，未解决区间仍在work_queue；全部可行方案耗尽或预算不足时才明确blocked，不能finish充数。

## 最终译片复核

先独立检查无字底片的原字清理和连续性，再对照译文字层的内容、大小、颜色、
位置与进出场。局部接受数不能证明整片清底完成，有残字的工作版不能交给译字。
执行顺序见项目操作文档`docs/operations/stage-quality.md`；
默认任务缺工具时保留清底工作版和真实阻塞。用户明确启用
review_draft_authorization 的任务，方法耗尽后可继续制作带问题的审看草稿：
逐项保留残字、运动和遮挡缺口，quality_passed=false，不虚构finish或清底覆盖。
最终批准针对该有问题版本的实际SHA；见`docs/operations/autonomous-best-effort.md`。

1. **锁定对象**：记录输入 candidate_sha256 与证据清单。完成条件：能说清每张图属于原片还是候选、对应时间与实际输入形式。
2. **逐项比对**：依次检查每个文字/人声ID的可用证据。对照原意与译文，再查看确实覆盖该时刻的候选图。完成条件：每个ID有证据类型、可定位来源和检查结论；仅有文本时标注text-only。
3. **划清未知**：根据共同方法资源和review提示词，把无法核实的切换、运动、遮挡持续性、声音、音乐与发音列入limitations。完成条件：每项未知都有具体受影响对象及人工需执行的检查动作。
4. **形成报告**：使用当前ReviewReport schema，缺陷按严重程度给出证据；covered_ids沿用“已执行逐项现有证据检查”的定义。完成条件：有修改证据则needs_revision，否则仍有媒体缺口则needs_human，报告不声称已完成未发生的播放或听验。
5. **交给人工**：把候选版本和需完整视听核实的要点交给任务界面。完成条件：报告注明模型阶段边界；最终交付批准由系统记录的人工决定绑定当前哈希，模型不能代替用户批准。
