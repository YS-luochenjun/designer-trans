# Route 与 Work

Route 管理整项任务、接收用户需求、协调 Work 并给出简短汇报。Work 在分配的制作领域内
观察原片、选择方法、制作和复核，使用实际可用的工具与受同一授权约束的子 Agent。
程序负责依赖、媒体身份、预算、原请求去重和质量门。
当前 `budget_policy` 优先于旧工单中的用量数字；测试不限额的启停与边界见
[资源预算](../operations/resource-budget.md)。质量、原请求和实际进展仍须核验。

## 调度与沟通

同任务默认最多两个就绪节点并行；独立音频与画面可以在前置条件满足后重叠执行。
共用底片和清底会话保持单一写入者，合成等待实际画面和音轨产物。
Work 的业务会话持久化，Codex CLI 按请求启动；不承诺一个常驻的 CLI 会话。

“与 Route 沟通”使用独立线程池，Work 运行时仍能回答。信息询问只回复事实，
明确修改追加方向，由 Work 在下一安全边界接收。发送消息保留输入和当前页面，
不默认暂停。需求歧义时由 Route 提出一个问题和二到四个业务选项。
已有的用户暂停保留，恢复制作使用显式任务控制。

用户首先看到 Route 的当前情况、下一步和必要决定。Work 原始日志可展开查看。
状态区分已转达、正在协调、已排队、实际制作、等待原结果与真实阻塞。
模型摘要和程序状态投影标明来源，不能以“消息已接收”代替实际制作。

## 报备与返工

Work 的交接绑定节点尝试、产物 SHA、质量、未解决范围及已知或未知费用。
正常成功由确定性依赖规则继续；方向变更、确定失败和审核不通过交 Route 队列。
Route 读取事实摘要与必要原证据，按原额度安排最早有问题的节点返工。
每个事件只诊断一次，守卫拒绝原计划不产生循环收费。

启动或派发巡检仅补交完全缺失的同节点、同尝试事实报告。
已有 blocked、unknown 或 superseded 结论不重开；原在途、未审候选、用户暂停、
删除和待处理消息优先。补报本身不制作、不改费用，由正常 Route 决定后续。
该能力的运行端标志是 health 的 `work_report_recovery_protocol_version=1`。

未知结果保留原请求身份，先核原回执；有效替代授权保留历史未知费用。
确定失败可有界换法，缺代码能力或额度耗尽时保留具体阻塞。
用户只处理真实业务选择与最终视听验收。

一条方法失败只结束该路线。Route 评估其他未完成实例与实际可用替代工具，
不把本地 Work 工单限制当成整个任务禁止生成，也不把原生生图不可请求当作 KIE 不可用。
完整候选的全局停止使用 `remaining_assessments` 逐实例给出证据、考虑方法及不适用原因。
不强制付费穷举；存在有据可做项就派工。依据不全时，在原额度和下游预留内
最多请求一次纠偏，原结论保留；仍不全则如实报告协调依据不足，不声称所有方法失败。
待核候选先审，不借此重投未知请求或绕过质量门。
运行端标志为 `clean_stop_scope_protocol_version=1`。
审核返工保留原具体缺陷，按素材和语言传入 Work 的新工作包，不污染其他分支。

## 新执行与阶段重置

显式新执行授权通过 `clean-execution-authorization` 登记有限追加动作窗口，
保留原会话、接受链、累计轮数和费用。授权只登记，由 Route 检阅后派工。

明确放弃旧清底及下游时，`clean-stage-reset` 先预览并绑定版本。
维护暂停、停稳和备份校验后，为清底及依赖阶段分配新身份，从原片、零接受开始。
独立音频、原片和上游分析保持；未结请求核账文件、累计调用和冻结资源继续保留。
重置保持暂停，之后的恢复与真实制作分别记录。

## 质量与加载

流程图展示程序状态，清底子图说明 Work 的制作循环，用户无需逐步点击驱动。
提示、知识和技能帮助 Work 判断，程序核验实际媒体、依赖与质量。
[逐阶段质量](../operations/stage-quality.md)规定清底和完整审核的门禁。
轻微正常观看纹理可披露；可读原文、叠字、主体损伤和缺少必需音轨属于未完成。

源码提交、隔离测试、生产加载、真实媒体质量和人工验收分别成立。
先维护暂停并保护所有活动任务，等在途停稳、核源码与业务记录，再通过原入口加载。
新资源版本仅进入新任务快照；代码加载不追认修改旧任务的冻结资源。
