# 连续片段制作与首页管家迭代方案

状态：分阶段实现中；时序模型选型、自动知识发布与完整批量验收仍需独立完成。

2026-11-11 已开展的基础优化是：原生窗口补片处理、可追溯的历史上下文投影、
显式节点依赖工作单与帧数/工作包计量。它们补强现有执行路径，
不等于下文完整 `TemporalRepairJob` 或时序引擎已经完成。
源码分发不携带本机验证记录；实际加载状态以运行端协议与独立维护回执为准。

随后按用户主动暂停与资源要求，增加新任务冻结资源预算和派发前检查。
历史任务保留各自的暂停与冻结预算。资源约束不能由新任务或方法切换绕过。

2026-11-11 后续已实现并隔离验证的子集：连续问题范围工作单、版本化上游交接、
管家固定维护意图、单任务事实总结候选、历史节点视频 SHA 计划与受守卫的退役执行器。
任务 Route 文件也计入同一资源预算。源码提交不代表运行端已经加载；
通用语义知识提炼/审核发布、自动镜头与 mask 时序传播、完整批量片段执行仍为后续工作。
当前运行合同见 [Route 与 Work](architecture/route-work.md)。

## 目标与问题定位

把业务工作单的默认单位从零散帧修改提升为文字实例的连续问题范围。媒体程序仍逐帧解码、跟踪与合成，Agent 在问题范围内决定方法和审查结果，异常边界再下钻到帧。

现有局部媒体方法支持明确时间段、关键帧轨迹和主体保护，并非所有处理都只能做一帧。执行层也已有去重、补片、缓存及收敛。需要修正的是端到端的任务粒度、质量复查单位和留存政策，不能仅增加一个模型名称或修改提示词。

旧项目的按镜头配方、候选复用和有限试验可作为参考，但其分段不是正确性的依据。新的划分要由当前文字运动、可用背景、遮挡、时序置信度和实际成本决定，也必须与固定窗口、旧分段和现行细粒度流程进行对照。官方方法与限制见[时序清底调研](temporal-removal-research.md)。

## 零、把三种粒度分开

| 层次 | 单位与边界 | 目的 |
| --- | --- | --- |
| 制作决定 | 同一文字实例或相互影响的实例组，其连续出现范围 | 一次规划与整段复核，减少模型往返 |
| 算法计算 | 有必要上下文与重叠的自适应窗口，受运动、遮挡和资源限制 | 控制内存与传播风险，窗口内仍计算每帧 |
| 存储 | 源视频、不可变局部补片、适量检查点及可再生缓存 | 避免算法窗口或决策轮次各保存一份完整视频 |

镜头切换是默认传播屏障，不要求一镜头对应一工作单。一个镜头内可以出现多个互不重叠的文字轨迹；跨镜头出现相同标题可以共享译文或样式，但不直接共享运动背景像素。不能为了减少工作单数量而跨遮挡强行拼接。

在质量和主体保护约束下，比较模型往返、解码/编码时间、峰值内存、增量字节和路线试验成本。先记录这些分项，再决定合并是否划算；不以帧数最少、段数最少或单模型分数最高作为唯一目标。

## 一、连续片段工作单

增加 `TemporalRepairJob`，冻结以下字段：

- 来源、当前底片及文件 SHA，原生帧率、尺寸与镜头 ID。
- 来源文字实例 ID、半开帧区间、上下文范围、逐帧移除 mask 与保护 mask。
- mask 来源：已观察关键帧、明确轨迹或经验证的检测/跟踪工具；未观察位置不得由插值假装可靠。
- 方法、适配器和权重版本，CPU/GPU/内存/时间/临时空间限制。
- 共享预算绑定、未知请求去重身份、有限路线试验与停止条件。

同镜头、同实例、同方法且没有遮挡/姿态切换的相邻工作段，在核对 mask 和质量条件后合并。同一镜头内可分重叠窗口供算法处理；不得跨剪辑点传播背景。

先利用现有轨迹覆盖、同镜头供体和参考底片能力完成整个可处理区间，再评估新时序引擎。低纹理背景、自然纹理、复杂运动和贴身文字分别选路；不能用同一静态图硬贴所有场景。

### 自适应划分与复用

1. 先核对可用原始图层、无字原片和已验证同素材底片，存在可靠来源时优先复用；新取得素材仍须核对身份、覆盖范围和使用权限。
2. 用低成本预览提出文字实例、镜头与遮挡变化点，再回到原生帧坐标验证掩码。预览漏字、原生字号过小或跟踪不稳时增加局部观察，不把低分辨率检测当最终证据。
3. 对静态背景尝试稳定供体或既有参考；相机运动下需要验证配准和前后向一致性，避免把不同透视或主体当作可复制背景。
4. 遮挡变换、跟踪失稳、背景供体不足、窗口资源超限时拆分；相邻范围条件一致时合并。同一业务工作单可由多个不同方法的计算窗口完成，保持清楚的逐帧覆盖映射。
5. 缓存以来源、实际影响帧、掩码、方法参数及版本为身份。底片局部更新只使相交的证据和依赖失效；仅有“同一镜头”或“相同时间段”不足以复用。
6. 稳定底片上互不重叠的局部编辑可进入一个有序批次。相交区域、父依赖或输入 SHA 改变时重新核验，不能把并行候选直接拼成已接受结果。

实现时先扩展现有区间、轨迹、引用与补片合同；只有现有接口无法表达的部分才增加新合同，不建立第二套制作引擎。跨语言共享同一合格清底层，译文、字层和语言音轨分别处理；语言版本数量不应导致相同清底重复制作。

## 二、批量执行与分层审核

1. Agent 提交一次片段工作单，程序完成掩码核验、连续处理与无损回贴。
2. 窗口重叠区验证时钟和差异，明确合成规则；保持非 mask 区域及主体保护。
3. 程序检查实际帧覆盖、边界、音轨、几何与外部结果回执，不能把技术通过变为质量通过。
4. Agent 对整个受影响片段审查，参考首尾内外帧、内部风险点与正常速度播放。采样点通过不等于整个区间合格；在模型不支持动态视频输入时，使用实际能力允许的证据检查，并明确动态审核的缺口。
5. 只有残字、闪烁或遮挡异常区进入小范围返工；不逐帧反复评分，也不反复检查无变化区域。
6. 完整视频重新合成后执行必要全片视听与语言审核，绑定当前结果 SHA。

预算和停止条件在片段工作单与整个任务上共同成立。子窗口、方法切换和重新生成工作单不能重置试验次数。失败应保留原因、切换依据和未解决内容，不能无限拆小以绕过收敛。

## 三、存储生命周期

把产物分为活动依赖、近期检查点、可再生缓存、必要审计记录和独立知识案例。

先实现只读依赖图与清理计划，再实现有授权的执行器：

- 从当前底片、候选、接受链、源资产、工作包及未决请求收集引用，递归核对补片父依赖。
- 对无引用历史媒体给出路径、大小、保留理由、是否可再生与证据保全状态。
- 原费用、未知结果、授权、重要拒绝与质量异议记录独立保留。
- 当前任务仍有活动写入时先报告可回收估计；无法证明引用稳定的媒体不进入删除清单。
- 执行绑定新鲜计划 SHA、精确工作区、策略版本、授权和上限，逐文件重核身份，记录部分失败与实际剩余空间。

禁止把文件年龄、候选名称或扩展名单独当作可以删除的依据。轻量交付包只保留成片和必要记录；需要可恢复工程时另按策略保留依赖，不默认复制完整制作现场。

## 四、首页管家：快捷提问与受约束能力

现行管家动作合同只包含暂停、恢复、重试和需求同步。不能通过追加系统提示，就声称已拥有项目清理与知识整理能力。建议保留同一个首页入口，在后端增加明确能力注册及请求合同。

本轮已在同一管理消息合同增加 `storage`、`cleanup_plan`、`knowledge_summary` 固定意图，
通过原管理队列本地执行，无需额外模型调用；能力查询接口返回快捷问句与真实边界。
清理问句只预览，无授权扩张；总结只保存带原记录 SHA 的事实候选。
下面的自然语言提炼、审核合并发布及自动生命周期策略仍是目标设计，不是本轮交付。

### 清理流程

`用户问题 → 只读分类/空间诊断 → 依赖图 → 清理计划 → 授权校验 → 执行 → 回执`

快捷问句示例：

- “为什么这个任务占空间？当前哪些是必需的？”
- “列出可以回收的历史产物，预计释放多少？”
- “按已授权策略清理可再生缓存，并报告实际空间变化。”

清理提示词约束：

> 你只解释提供的文件清单、依赖、策略与运行状态。先区分逻辑大小和可回收大小；每个建议说明依据。不得生成 shell 删除命令或自行挑选任意路径。只能引用执行器返回的计划 ID 与 SHA。没有对应授权、存在未决请求或依据失效时，仅报告阻塞原因和下一步。不声称建议已经执行，不改变费用、质量或验收状态。

结构化输出至少包含 `intent`、`task_ids`、`facts`、`plan_id`、`expected_plan_sha256`、`authorization_id`、`blocked_reasons`、`user_reply`。真正删除仍由固定执行器完成。

### 知识总结流程

`用户问题/结案事件 → 有来源的增量证据 → 分类候选 → 范围与反证审核 → 合并/发布 → 版本化索引`

快捷问句示例：

- “这次失败有哪些可复用经验？依据是什么？”
- “总结本周重复问题，区分项目通用方法和单素材案例。”
- “把已审核的经验整理进知识库，并列出未验证推断。”

总结提示词约束：

> 仅依据提供的实际事件与证据总结。逐条区分观察、推断和建议，引用来源 ID、正文 SHA 与必要结果身份。失败不总结为成功，合成测试不写成真实视频实证。单源经验不扩大为通用结论，同义且同范围才合并。自动输出进入候选区；质量门槛、公司偏好、预算和生产工具权限不随总结改变。保留反例、限制、旧版本与待复验项。

结构化候选至少包含 `observations`、`source_refs`、`hypothesis`、`scope`、`limitations`、`counterexamples`、`suggested_action`、`target_ids`、`review_status`。写候选与启用生产知识是不同权限；现有任务的冻结资源不被静默替换。

两类维护应有独立队列、幂等身份、费用限额、取消、超时与未知结果核对。知识提炼失败不能把任务重新制作，清理失败不能删除知识来源。

### 快捷问答与能力验收

自然语言由管家映射为固定意图；“看看占用”只产生查询，“总结一下”只产生候选。“清理项目”等宽泛表述先返回对象、分类与可执行范围；已有持续授权范围内的安全执行无需逐文件追问，超范围操作不能从聊天语气推断授权。

文件名、日志、任务文本与旧总结都作为不可信数据，不得改变系统权限。检索只返回当前问题需要的脱敏事实、证据 ID 与来源摘要，不把凭据、全量历史或整库媒体塞入提示词。

验收样例至少包括：活动补片父依赖被保护、跨任务引用被保护、计划生成后文件变化拒绝执行、取消及授权撤销立即生效、部分删除中断可核对原回执、同一总结重复触发不写重复候选、单源失败不推广为通用规则、反证和未决费用不会因总结消失。问答还需验证引用可追溯、无证据时明确未知，以及候选/计划/已执行状态不会混淆。

## 五、开发与验证顺序

1. 只读统计片段粒度、模型轮数、实际处理时间与增量字节，建立基线。
2. 扩展片段工作单和同镜头合并，在合成样例锁定剪辑点、遮挡与未知去重。
3. 用现有工具完成整段执行与一次片段审核，验证不绕过预算或质量门禁。
4. 独立评估时序引擎的代码/权重许可、资源消耗和真实困难片段；未通过前不注册生产。
5. 建立依赖图与清理计划，核验当前底片/候选/未决请求保留，再启用有界清理。
6. 接入首页管家的只读问答，再分开开放候选知识写入、审核发布和清理执行。

验收应报告每秒视频的 Agent 操作数、片段/路线次数、首次候选耗时、返工耗时、峰值临时空间、每次修复新增字节与实际回收空间。与原输入、同范围、同质量约束比较，不能预先承诺固定倍数的提速。

对照至少覆盖静态字幕、运动背景、遮挡主体、剪辑边界和低清小字。分别比较现行细粒度、旧分段复用、自适应范围与候选时序方法；保留失败与人工评审依据。只有兼顾质量和总成本的方案进入默认路线，不能因开源项目演示效果或少量合成帧成功直接替换当前生产。
