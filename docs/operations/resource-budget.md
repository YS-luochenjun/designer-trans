# 资源预算

新任务将资源预算冻结进 `execution_snapshot.resource_budget`。
默认任务工作区为2 GiB、10,000文件，保留1 GiB磁盘余量；
项目外部调用80次、技术恢复8次、清底48轮。业务图片、视频及服务商额度另行约束，
取实际更严格的上限。调用次数不是金额。

派发模型、图片、恢复和媒体写入前检查任务累计用量与本次估计。
目录统计包含任务目录与 Route 目录；共享原片、全局 CLI 日志、依赖、权重另计。
这是入口预检和停止阈值，不能作为操作系统硬配额或峰值空间预留承诺。
Work 的工具与子 Agent 继续共享原授权和预算。

完整候选模式下，清底轮数和无进展动作触发有界 Route 复盘。
真实调用、存储、业务金额和质量约束保持，触限不自动扩额或清空用量。
未知调用费用保留原身份；方法切换、重启和重新派工不清零计数。

明确授权后，`supervision-budget` 可绑定版本增加有限协调与返工额度；
`clean-execution-authorization` 可登记有限追加动作窗口。
两者均不代替实际制作，不默认恢复暂停，不自动提高其他预算。
显式阶段重置将旧阶段移出当前制作，原费用和总调用继续累计。

空间清理以当前底片、递归补片父链、接受链、候选、原工作包和未决请求为依据。
受控历史退役先生成新鲜计划，核授权与文件 SHA，再记录实际删除回执。
无法证明依赖稳定时保持原文件。源码发布不触碰生产媒体和业务记录。
